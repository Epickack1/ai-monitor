# AIMonitor

Консольное приложение для отслеживания доступности моделей искусственного интеллекта в сервисе OpenRouter.

## Назначение

OpenRouter даёт доступ к сотням моделей ИИ через единый API, но каждую модель обслуживают разные провайдеры, и любой из них может работать с перебоями. AIMonitor показывает, какие из выбранных моделей сейчас доступны, сколько провайдеров у каждой работает и каков их аптайм. Так перед подключением модели к своему проекту видно, стоит ли на неё рассчитывать.

## Целевая аудитория

- Разработчики, которые используют модели ИИ через OpenRouter в своих приложениях.
- Студенты и исследователи, которые выбирают модель, в том числе бесплатную.
- Администраторы сервисов с ИИ, которым важно заранее узнавать о сбоях моделей.

## Предметная область

Мониторинг доступности моделей ИИ. OpenRouter публикует каталог моделей и для каждой модели список провайдеров: их статус и процент времени без сбоев (аптайм) за последние 5 минут, 30 минут и сутки. На основе этих данных приложение определяет состояние модели. Дополнительно, при наличии API-ключа, модель можно проверить живым запросом с замером времени ответа.

## Объектная модель

Сущности предметной области представлены классами пакета `models`. Коллекции приложения — это списки объектов: `list[AIModel]` (список отслеживания и каталог), `list[CheckResult]` (история проверок).

### AIModel — модель ИИ

Модель из каталога OpenRouter.

Атрибуты:
- `id` — идентификатор в OpenRouter, например `openai/gpt-4o-mini`; свойство только для чтения (хранится в `_id`), потому что по нему с моделью связана история;
- `name` — название;
- `price` — цена токена запроса и ответа, `None`, если неизвестна;
- `FREE_SUFFIX` — атрибут класса, суффикс бесплатных моделей `:free`.

Методы:
- `is_free` (`@property`) — бесплатная ли модель;
- `matches(query)` — есть ли подстрока в id или названии;
- `to_data()` — данные для JSON;
- `from_data(data)` и `from_api(data)` (`@classmethod`) — создание объекта из JSON-файла и из ответа OpenRouter;
- `validate_id(model_id)` (`@staticmethod`) — проверка формата id;
- `__str__()` — «Название [бесплатная] (id)».

### Provider — провайдер

Компания, которая обслуживает модель.

Атрибуты: `name`, `status` (0 — работает, меньше 0 — сбой), `uptime_5m`, `uptime_30m`, `uptime_1d` (аптайм в процентах).

Методы: `is_working` (`@property`), `from_api(data)` (`@classmethod`), `__str__()` — строка таблицы провайдеров.

### CheckResult — результат проверки

Одна проверка доступности модели.

Атрибуты: `model` — объект `AIModel`, `status`, `uptime`, `checked_at`, `providers` — список объектов `Provider` на момент проверки.

Методы: `is_available` (`@property`), `from_providers(model, providers)` (`@classmethod`) — оценка доступности по провайдерам, `from_data(data, model)` (`@classmethod`), `to_data()`, `__str__()` — «время статус аптайм».

### ModelStats — статистика модели

Накопленная статистика проверок одной модели.

Атрибуты: `model` — объект `AIModel`, `checks`, `available`, `uptimes`.

Методы: `add(result)` — учесть проверку, `percent` и `avg_uptime` (`@property`), `__str__()` — строка таблицы статистики.

### Взаимодействие объектов

```
CheckResult
├── model ──→ AIModel
└── providers ──→ [Provider, Provider, ...]

ModelStats
└── model ──→ AIModel
```

`CheckResult` хранит ссылку на объект модели, а не только её id: данные модели доступны как `result.model.name`. Все проверки одной модели ссылаются на один и тот же объект `AIModel`. Статус модели вычисляется по её провайдерам: `CheckResult.from_providers(model, providers)`.

Операции над коллекциями остаются обычными функциями модулей: поиск и добавление моделей (`models/ai_model.py`), оценка статуса по списку провайдеров (`models/provider.py`), история, статистика и сортировка (`models/check.py`).

Декоратор `@timed` (`utils.py`) замеряет время работы функции. Он применяется к `send_test_prompt()` в живом тесте модели.

## Основные функции

1. Проверка доступности всех отслеживаемых моделей со сводкой.
2. Подробная проверка одной модели с таблицей всех её провайдеров.
3. Просмотр списка отслеживаемых моделей с результатом последней проверки и сортировкой по названию или по аптайму.
4. Поиск модели в каталоге OpenRouter, в том числе только среди бесплатных.
5. Добавление модели в отслеживание и удаление из него.
6. Живой тест модели: короткий запрос и замер времени ответа (нужен API-ключ).
7. Сохранение каждой проверки в историю (`data/history.json`).
8. Статистика доступности по истории: число проверок, доля успешных, средний аптайм, самая стабильная и самая проблемная модель.
9. Просмотр последних проверок выбранной модели.

Все данные сохраняются в JSON-файлах и загружаются при запуске. Некорректный ввод, отсутствующий или повреждённый файл данных не приводят к аварийному завершению программы.

## Как определяется статус модели

| Статус | Условие |
|---|---|
| Доступна | есть работающий провайдер, аптайм лучшего из них за 5 минут не ниже 90% |
| Нестабильна | провайдеры работают, но аптайм ниже 90% |
| Недоступна | ни один провайдер не работает |
| Не найдена | модели нет в OpenRouter или нет связи с сервисом |

Провайдер считается работающим, если OpenRouter сообщает для него статус `0`; отрицательный статус означает сбой.

## Формат данных

`data/watchlist.json` — список отслеживаемых моделей:

```json
[
  {
    "id": "openai/gpt-4o-mini",
    "name": "OpenAI: GPT-4o-mini"
  }
]
```

`data/history.json` — история проверок. `uptime` — лучший аптайм работающих провайдеров за 5 минут (при отсутствии данных — за 30 минут), `null`, если данных нет. Хранится не более 1000 последних записей.

```json
[
  {
    "model_id": "openai/gpt-4o-mini",
    "status": "Доступна",
    "uptime": 99.8,
    "checked_at": "2026-09-26 14:05"
  }
]
```

Записи с неверной структурой при загрузке пропускаются.

JSON используется для хранения, объекты — для работы программы. При загрузке `storage.py` создаёт объекты `AIModel`, а для каждой записи истории находит объект модели по `model_id` и передаёт его в `CheckResult`. Если модель уже удалена из отслеживания, её история не теряется: для неё создаётся объект `AIModel` с названием, равным id. При сохранении объекты превращаются обратно в словари методом `to_data()`, а вместо объекта модели записывается её `model_id`.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS
pip install -r requirements.txt
```

Для живого теста скопируйте `.env.example` в `.env` и впишите ключ с https://openrouter.ai/settings/keys. Остальные функции работают без ключа.

## Запуск

```bash
python main.py
```

## Тесты и проверка кода

```bash
pytest -v
flake8 --exclude .venv
```

Тесты проверяют создание объектов и значения их атрибутов, методы и свойства классов, строковое представление, связь `CheckResult` с `AIModel`, определение статуса модели по провайдерам, историю и статистику, преобразование JSON в объекты и обратно, обработку повреждённых файлов и декоратор `timed`.

## Технологии

- **Python 3** — основной язык
- **urllib** — HTTP-запросы к OpenRouter (стандартная библиотека)
- **json** — хранение списка моделей и истории проверок
- **pytest** — автоматизированные тесты
- **flake8** — проверка оформления кода
- **Git / GitHub** — контроль версий
